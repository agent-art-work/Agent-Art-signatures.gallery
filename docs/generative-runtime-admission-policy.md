# Sepolia generative runtime: admission policy and implementation order

September 23, 2026. **Offline operating-plan validation, read-only active-state observation, local single-operation admission adapters, review-file startup and the staging database structural checker are implemented. Public runtime composition and operational admission are not.** The agreed target is Ethereum Sepolia at `https://staging.signatures.gallery`. All existing generative backend/site/wallet/recovery entrypoints still refuse public startup and remain local 31337 only. [Validator scope](generative-operating-plan.md), [active-state scope](generative-active-state-verification.md), [admission boundary](generative-admission-composition.md) and [database checker scope](generative-database-certification.md).

## Separate the decisions

Deployment approval, verified deployment, runtime readiness and mint activation are different decisions. Do not collapse them into a manifest field, environment flag or operator-supplied `approved: true` report.

| Stage | Required evidence / authority | Allowed effect |
| --- | --- | --- |
| Candidate review | Exact release lock; internal numerical/security evidence; independent review and recorded disposition of findings | Offline implementation and tests only |
| Operating plan | Explicit owners, accounts, limits and deployment bindings below | Produce an inspectable plan; no provisioning or signing |
| Approved paused deployment | Separately scoped approval of chain, constructor inputs, custody and spending | Deploy exactly the approved candidate, paused; never auto-unpause |
| Observed initial deployment | Fresh two-source pristine-deployment witness, matching the plan and actual signed CREATE transactions | Evidence that the paused deployment matches; not public admission |
| Prepared runtime | Exact durable/runtime bindings, explicit migrations and grant audit, read-provider acceptance, approved operating plan | Initialize the new deployment with issuance disabled; run read-only readiness checks |
| Verified activation | Explicit activation decision plus canonical finalized role-authorized unpause receipt and audited intervening history | Permit the separately reviewed runtime to evaluate mint admission |
| Live admission | Fresh active-state evidence plus database ownership, budget, session, signer and kill-switch checks | Admit a single user-requested operation under its normal durable workflow |

Each later stage depends on earlier evidence but does not reuse a stale process-local witness. Restart reconstructs observations; a serialized report is for audit only. A failed/stale check disables **new paid dispatch and authorization issuance**, without discarding saved assessments, signed permissions, wallet submissions or minted tokens.

## Exact operating-plan bindings

No provider, custodian or hosting account is chosen implicitly from local configuration. The reviewed plan must bind:

- Release-lock digest, collection/renderer versions, input profile, chain **11155111**, published Sepolia genesis, deployment transaction hashes/block hashes, exact deployed code/immutables, renderer identity and EIP-712 domain.
- HTTPS origin **staging.signatures.gallery**, dedicated staging namespace/deployment ID, allowed proxy hops/origin policy, session and CSRF scope. Never reuse `local-real` rows or cookies in staging.
- Two separately operated RPC sources with declared ownership and tested block-hash/finality/historical-state support. Different URLs alone are not evidence of independence. Secrets stay out of reports. Test complete metadata reads under the shared gas/byte/deadline policy and actual transport streaming caps; the local campaign is not provider acceptance.
- Deployer, delayed admin, authorizer manager, pauser, nonce revoker and authorizer addresses and responsible owners; secret storage/signing arrangements; compromise response and approved admin delay. Address labels are not custody evidence. Never use Anvil keys or restore a compromised signer.
- Dedicated PostgreSQL database/roles, exact additive schema profile and migration history, writer fencing, disabled initial issuance, backup/restore evidence and operator recovery permissions. Do not relabel historical deployments or migrate at server startup.
- Hosting/TLS/process ownership, readiness/liveness distinction, bounded queues/concurrency/timeouts, restricted outbound dependencies, redacted diagnostics and a reviewed operator/support route.
- Explicit spend reservations, dispatch concurrency, limits and unresolved-liability handling, selected provider request profile/credentials and paid-call approval envelope. “Runtime admitted” must not mean unlimited provider spending.
- Inclusion versus finality policy, reorg/halt handling and accepted compatibility evidence. Reveal only at verified canonical inclusion with **Confirming**; finalized-only gallery promotion remains unchanged.

The selected network/origin are already user decisions. Actual owners/accounts/custody, resource provisioning and public deployment/activation are not. Implement schema validation and mock/local tests without inventing those choices; request them together when preparing the operational plan.

## What must be implemented next

1. **Typed immutable operating-plan validator — implemented offline.** [The validator](generative-operating-plan.md) accepts explicit public identifiers and secret references, enforces exact fields/cross-bindings and the locked release/constructor/runtime identity, and rejects known test identities, crossed custody, unsafe defaults and admission flags. It returns deeply frozen, hashed declarations, not an admission capability. References do not prove custody, source independence, review or evidence. No credentials or public state are touched.
2. **Active-state observer distinct from the pristine observer — implemented, read-only.** The [new verifier](generative-active-state-verification.md) matches complete bounded history to explicit finalized activation/governance transactions, recovers their signed senders, replays role/signer/pause/nonce changes and checks exact code/domain/renderer/state at finalized and latest pins. Undeclared or unsupported changes stop verification, even when later reversed. The pristine observer remains unchanged. This first version supports direct EOA type-2 operational calls only; admin transfers/delay changes, renunciation and multisig execution halt pending a reviewed extension. A matching declaration proves neither human approval nor custody; the next admission layer must bind reviewed transition policy and rotated principals to the operating plan.
3. **In-process admission composition — isolated local RC1 integration, file-backed startup and separate staging DB checks verified; public operational admission pending.** The [single-operation gate](generative-admission-composition.md) binds fresh opaque chain evidence, operating/review/database digests, writer epoch and exact intent to a single-use permit. Execution obtains a fresh durable lease, awaits the existing operation fence and rechecks before the registered handler; checkpoints also run at the actual X/Grok fetch boundary and forward cancellation. The opt-in `LocalAdmissionRuntime` connects the real worker, private saved assessment/signature reuse, issuer and browser submission path. Disposable PostgreSQL tests exercise deadlines, shutdown, review withdrawal, invalid results, proof changes, exact saved reuse and no automatic retry. Earlier disposable Anvil/browser runs verify one local wallet send, Confirming reveal, finalized gallery and chain-only recovery. Paid HTTP is mocked and review keys are ephemeral fixtures. The existing site is not switched, and the public observer is not relaxed to admit Anvil. Narrower local database digests and fixture reviews remain **neither public certification nor operational authority**. The new staging checker is a separate disabled-policy snapshot, not a live admission adapter. Public startup remains refused until the separate composition and operational admission are complete.
   **Local file-source follow-through implemented:** [operator-pinned review loading and startup/recheck](generative-local-review-startup.md) verifies explicit bounded owner-only files, independent public-key/revision pins, current writer/database bindings and safe withdrawal/rotation behavior. Real custody/evidence has not been supplied or approved by the tests.
   **Database follow-through, September 23:** the [exact staging structural checker](generative-database-certification.md) now compares pinned migration-source/schema/grant identities and independently reviewed disabled policy profiles in one catalog snapshot. **164 mutation/transport/configuration tests pass.** System ACL drift, trigger/constraint changes, numeric rounding, malformed observations and timeout/cancellation are covered. Results remain observations, not permits; migration receipt pins are commitments, not authenticated historical evidence. Next implementation is step 4: integrate these bindings with a separately gated, resource-limited Sepolia composition and offline/disposable tests. Public startup is still refused; operational evidence must still be supplied independently.
4. **Explicit Sepolia runtime composition.** Add a separate entrypoint after the preceding pieces are reviewed; do not weaken `assertIsolatedGenerativeBinding` or repurpose local launch flags. Check bindings before writes, before listening and throughout operation. Require explicit role-audited initialization. Refactor shared adapters only with both-profile/local-refusal regressions intact.
5. **Operational observation/rehearsal.** With approved accounts/resources, validate real RPC limits and custody, deploy paused under the approved plan, observe it, and prepare issuance-disabled runtime. Obtain a separate activation decision, observe activation and execute the bounded staging rehearsal. Real wallet-extension/device and independent-review evidence remain distinct from injected-wallet/Anvil results.

Steps 1–4 can be developed with offline fixtures and isolated local tests; missing real accounts do not justify enabling public startup. Step 5 crosses the operating/approval boundary. If independent review requires source changes, introduce a newly versioned candidate and rerun all bound evidence before continuing; never bless a changed RC by rewriting its lock.

## Failure and recovery rules

- Missing/stale/conflicting RPC evidence, unexpected privileges, signer/code drift, loss of writer ownership, exhausted/uncertain spend, paused collection or disabled issuance prevents a new effect. No automatic paid retry, reroll, replacement authorization, nonce-gap filling or unpause follows.
- Chain observation and safe read service may continue only while their own evidence is valid. An unavailable read is not evidence of “unminted.” Cached finalized artwork is bound to exact deployment/token provenance; no alternate remote canonical artwork is substituted.
- Disabling the backend does not revoke an already signed authorization. Contract pause, nonce revocation and finalized expiry have different meanings. The [review's signer-restoration findings](generative-numerical-security-review.md#security-findings-and-operating-consequences) are part of incident response. A 900-second wait alone cannot neutralize unknown future-dated signatures from a compromised signer.
- Preserve uncertain wallet/provider outcomes across restart. Existing [operator recovery](generative-operator-recovery.md) stays local until separately ported/reviewed; do not expose it as a public “clear” button or silently widen its accepted evidence.

Required regression matrix for the new admission composition: all crossed configuration fields; wrong genesis/code/immutables/domain; forged/copied/expired evidence; stale finality/reorg/provider disagreement; unapproved role history; restart and configuration drift; writer loss and policy changes immediately before dispatch/signing; public request forged flags; disabled/unfunded/exhausted spend; saved accepted assessment/authorization reuse without new dispatch; read-only service with issuance disabled; unchanged refusal of historical/local profiles on public targets.

No completed SVG storage, compression, IPFS publication or caller-supplied output hash is part of this plan. The contract still mints compact authoritative inputs and computes artwork on reads.
